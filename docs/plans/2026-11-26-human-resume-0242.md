# 0.24.2: human-only resume, owned closes, the stop LOWs

Decided by Kristian (2026-11-26). Base: main 4a6c790.

## 1. H1 - a human stop is lifted only by the human
- Second shared manual-reset event `Local\ghost-emergency-stop-human`, raised together
  with the stop event by Ctrl+Alt+G. `is_stopped()` = local flag OR stop event OR human
  event, so a race between an agent reset and the hotkey can never lower a human stop.
- MCP `ghost_reset` (scope everywhere) refuses while the human event is up, naming the
  human's ways out; `ghost_stop` raises only the stop event (an agent stop stays
  agent-liftable). `scope: "process"` is unchanged (local flag only).
- The human resumes with Ctrl+Alt+Shift+G (registered on the hotkey thread; a thread
  timer retries both registrations so ownership migrates) or `ghost reset` in a terminal
  (new CLI subcommand, not gated).
- Linux/macOS: the same API over process-local flags (no shared event there).
- Tests: per-process event names under `cfg(test)`, child processes for anything that
  raises them. Never the real shared events.
- Live proof: a PRIVATE build with the `isolated-stop-events` cargo feature (never in a
  release: the release workflow builds default features) that takes event names from
  `GHOST_ISOLATED_STOP_NS`. Raising a "human" stop there = PowerShell SetEvent on the
  isolated names. The published binary is also shown to ignore that variable.

## 2. Close tools during a stop
- `ghost_tab_close`, `ghost_browser_close`, `ghost_desktop_close` become Control at the
  MCP gate; ownership is enforced in the session layer: while stopped, closing is allowed
  only for a browser Ghost launched (and its tabs) and for Ghost's hidden desktops.
  `ghost_window op=state close` (the user's windows) and tabs of attached browsers stay
  refused. ghost-browser `close_tab` backstop allows owned browsers.

## 3. The open LOWs (Kristian's scope addition)
- (a) A stop after a server restart reaches the old server's shell children: each server's
  shell job is named and listed in a per-user directory; a shared stop terminates every
  listed job that still exists (process-scope stops only the server's own).
- (b) Linux: shells start in their own process group; the stop kills each group.
- (c) Wording: the fail-closed text everywhere (verify skip, lower layers), a shell ended
  by an earlier stop no longer reported as stopped after reset (stop generation counter
  instead of exit code 57005), dead shell sessions pruned from the registry.
- (d) Live proofs with the private build: stop ends a persistent shell session, the exact
  fail-closed refusal over MCP, a process-scoped reset cannot lift a shared stop.

## Kristian's decisions after audit round 1 (BLOCK on H1)
1. Agent-facing text (refusals, ghost_reset error + description) says only: the human
   stopped Ghost; only the human can resume it; wait for them. Resume methods appear only
   in README and CLI help.
2. `ghost reset` requires an interactive console (stdin is a console) plus a typed random
   challenge word; pipes/scripts fail. Ctrl+Alt+Shift+G is read by a WH_KEYBOARD_LL hook
   that ignores injected keys (LLKHF_INJECTED), not RegisterHotKey. Document the remaining
   limit: same-user code can still reset the named event directly.
3. Shell snapshots: keep LOW (a), with guards - expire after 24 h and at reboot, end only
   processes still inside a job object; document; LOW.
Also from round 1 (no decision needed): Linux pgid reuse guard (leader start time), a
compile_error! guard so `isolated-stop-events` cannot build in release (private builds are
debug), log when the resume hook cannot install.
